# Valheim Russian Pack 0.1.2 — изменения и повторное ревью

> Исторический документ версии 0.1.2. Текущее состояние — [CHANGELOG.md](../CHANGELOG.md)
> и [VALIDATION.md](VALIDATION.md). Упомянутые ниже Install.ps1/Install.cmd в 0.1.3
> удалены, протоколы 0.1.2 перенесены в [evidence/0.1.2](evidence/0.1.2/).

Дата: 28 сентября 2026. Основание: ревью переиспользования 0.1.1 и последующая доработка. Ниже сохранены результаты и ограничения этапа 0.1.2; они не подтверждают текущую сборку.

## Итог по границам задачи

Замены общей рефлексии, IL labels, нативной регистрации, сборочного и тестового
контура реализованы в исходниках. Python больше не изображает компилятор или игровой
переводчик. Данные всех 37 модулей сохранены без изменений и прошли независимую
сверку с исходным handoff.

**Работоспособность C# и готовый бинарный релиз не подтверждены.** .NET SDK/Mono,
игровых библиотек и PowerShell здесь нет; dotnet test не запустился. DLL отсутствует.
Миграция универсального UI-слоя на XUnity не выполнена: API сопоставлены, но проверка
на самой сборке остаётся открытой. Это ограничение не скрывается за успехом данных.

## Что дополнительно найдено и исправлено при доработке

### Повторная регистрация нашего русского могла затереть уже существующий

`src/LocalizationBridge.cs`, BeforeAddWord. Наше значение может вернуться в игру
через нативный scope Jötunn. Теперь вход, совпадающий с нашим русским, подчиняется
тому же fill-only правилу, что английский fallback. Чужой существующий русский
сохраняется, а последующая другая явно русская запись может заменить наш fallback.
Добавлен сценарий в HarmonyTests. Вывод по коду; игровое воспроизведение не заявляется.

### Кэш мог сохранить текст до появления нового native key

Нативный загрузчик может записать слово непосредственно перед Rebuild, когда наш
перехват ещё не знает ключ. Refresh теперь сбрасывает кэш полной строки через
штатный EvictAll даже если нужный перевод уже лежит в основном словаре и новой
записи AddWord не требуется. Добавлен сценарий поздней регистрации ключа.

### Неудачная повторная привязка оставляла прежний runtime context

CatalogLoader.TryBind сначала сбрасывает RuntimeAssembly, Table, ExactVersion и
UiAllowed. При missing/неверной идентичности старый разрешённый модуль не остаётся
активным. NUnit проверяет последовательность успех → разрешённая другая версия →
отсутствующий модуль. Проверка metadata на Python не выдаётся за этот runtime-тест.

### Nullable context и ошибки очистки

Публичные TextEngine entrypoints сохраняют исходную строку при null moduleId,
null literal или отсутствующей Table, вместо ошибки у вызывающего UI.
Ошибка отписки Jötunn логируется и больше не прерывает очистку остальных патчей.
Состояние LocalizationBridge/LegacyDisplay очищается при ошибке запуска и уничтожении.

### Расхождение проверенного и поставляемого результата

Build.ps1 сравнивает DLL production output с DLL test host, все 37 каталогов — с
их тестовыми копиями. Упаковывается только проверенный набор, не произвольный bin.
Пустые/пропущенные тесты запрещены в пакетном пути. Ранее собранный ZIP переносится
отдельно перед новым прогоном; новый публикуется после успеха. MSBuild создаёт каталог
для reference-hashes до записи отчёта. Это проверки в исходниках, не исполнявшийся
Windows build-процесс.

### Проверка только ZIP-файлов оставляла непроверенными имена директорий

Install.ps1 теперь проверяет и директории, и файлы по разрешённой структуре, отклоняет
дубликаты путей без учёта регистра и аномальные размеры. Проверка происходит до
распаковки в temp/изменения профиля. Хеши receipt контролируют целостность, но не
аутентичность источника. История 0.1.1 не переписана как доказанный exploit; это
дополнительное усиление нового copy-only установщика при собственном ревью.

## Исполненные проверки

4352 утверждения данных с исходным handoff, 0 ошибок, 0 пропусков. Pytest: 6 passed,
включая чистый набор и пять различающих мутаций. Первая попытка одного мутационного
теста содержала ошибку подготовки; исправлена, не засчитана как обнаружение дефекта.
Подробности и протоколы — VALIDATION.md и docs/evidence.

Два csproj и один props разобраны стандартным XML-парсером. Это не проверка MSBuild
semantics. Python-файлы прошли py_compile. Все 37 каталожных файлов побайтно совпали
с 0.1.1. SHA256SUMS/CRC — отдельные проверки упаковки.

## Незакрытые проверки и сохранённые ограничения

Нужны реальная компиляция/NUnit, boot BepInEx с настоящими модами, Harmony в Unity/Mono,
совместная работа с другим пакетом перевода/Jötunn/LocalizationCache, UI и языковая смена, установка
и rollback в Windows, сохранения, multiplayer. Не утверждается ни успех этих сценариев,
ни доказанная ошибка игры только из-за отсутствия среды.

Чужой Jötunn scope всё ещё находится через internal реестр; cache игры сбрасывается
через private member и существующий EvictAll. Эти адресные compatibility-адаптеры
могут требовать изменения при обновлении зависимостей. Public GetLocalization для
своего плагина не заменяет доступ к чужому scope.

Собственный UI-transpiler оставлен для текущих потребителей, не расширен. XUnity
обсуждается не как неподходящий продукт, а как непроверенная замена конкретного
контракта. Условия решения перечислены в REUSE-DECISIONS.md. Нельзя утверждать,
что весь общий UI-слой уже передан готовому решению.

Исходный результат «готовый мод с DLL» по-прежнему не поставлен. Исправленный
исходный архив полезен для следующей реальной сборки, но не подменяет бинарный релиз.

## Аудит 0.5.3: самописное и готовое

Код мода, сборка и валидатор проверены на самописные решения там, где есть библиотека или
стандартное средство. Заменено:

| Было | Стало | Чем подтверждено |
|---|---|---|
| Ручные проверки `null` в CatalogLoader; раздел с опечаткой в имени молча пропускался | Контракт Json.NET на типах каталога: `MissingMemberHandling.Error`, `ItemRequired = DisallowNull` | Тест `CatalogShapeIsEnforcedWhileReading`: пять испорченных каталогов отклонены |
| Посимвольный разборщик шаблонов табличек CLLC в C# и другой, на подстановках, в Python | Одно регулярное выражение — в схеме каталога и в загрузчике | Тест сверяет выражения; прежние 14 случаев шаблонов проходят |
| Структурные проверки `validate.py`, написанные вручную | JSON Schema `tools/catalog.schema.json` и библиотека jsonschema | Три новые порчи в pytest: опечатка в разделе, `null`, пустое значение |
| Ширина и высота иконки из байтов заголовка PNG | System.Drawing декодирует картинку и сообщает формат | Контроль пакета «иконка JPEG 256×256» отклонён |

Оставлено своим, с причиной:

| Механизм | Почему не библиотека |
|---|---|
| Шаблоны TextEngine: обратный разбор строки с типизированными аргументами (`text`, `term:`, `message`) | Готового обратного форматирования с такой семантикой для .NET 4.8 нет; сопоставление выполняет стандартный Regex |
| Ограниченные кэши TextEngine и RawDisplay (очистка при переполнении) | Одна строка кода; `MemoryCache` добавил бы зависимость, наличие которой в Mono игры не проверено |
| Проверка готового ZIP в Build.ps1 | tcli собирает ZIP по `thunderstore.toml`; раскладка `plugins/`, хеши DLL и каталогов, манифест без BOM — требования этого проекта к результату |
| `tools/Test-PackageCheck.ps1`, а не Pester | В системе только Pester 3.4 (2016); его синтаксис не работает в Pester 5, а установка Pester 5 меняет машину ради 50 строк контролей |
| SHA-256 через .NET в Build.ps1 | `Get-FileHash` не загружается в Windows PowerShell, если PSModulePath унаследован от PowerShell 7 (комментарий в скрипте) |

## Сравнение с XUnity.AutoTranslator

Первичный источник: https://github.com/bbepis/XUnity.AutoTranslator . Проверялись
manual/plugin-specific translations, отключение автоматического перевода пустым
Endpoint, Mono UI hooks (UGUI/TextMeshPro/IMGUI), API регистрации таблиц. Это реальная
готовая альтернатива значительной части общего UI-механизма; отсутствие кандидата
не является причиной сохранять собственный движок.

Но заявленная функциональность не подтверждает замещение данного контракта:

| Сценарий | Возможность XUnity по документации | Что требуется доказать на нашей сборке |
|---|---|---|
| IMGUI TradersExtended | IMGUI и plugin-specific таблицы есть | Вложенные ошибки переведены, имена файлов и ID не меняются |
| TMP PortalLines | Перехват текста TMP есть | Существующий toggle переключает RU/EN вместе с игрой |
| Метки карты | Текстовый UI можно переводить | Исходные имена, пользовательский ввод и чужие переводы сохранены |
| Выключенная сеть | Endpoint можно оставить пустым | Конкретная конфигурация не обращается к переводчикам |
| Уже установленный пакет перевода | Система принимает готовые словари | Не возникает двойного перевода/конфликта Harmony/кэша |
| Ограничение версиями мода | Есть plugin-specific scope | Наша GUID/assembly/version-политика не теряется |

Собственная настройка Language у XUnity сама по себе не является интеграцией с
SetupLanguage Valheim. Регистрация готовых пар сама по себе не переносит правила
`message`/`mapLabel`/непрозрачных параметров. Эти различия требуют проверки, а не
предположения, что библиотека непригодна.

**Статус: сравнение API выполнено, пригодность замены не установлена.** Пилот с
XUnity в игре не выполнялся. Дополнительный
глобальный переводчик не добавлен поверх имеющихся перехватов. Существующие UI-потребители
сохранены, чтобы не выдать непроверенную миграцию за исправление. Решение не означает,
что XUnity отвергнут навсегда или весь custom UI-слой обоснован на будущее.

Условие следующего решения: на копии профиля провести эти пять UI/coexistence сценариев
и version-policy проверку; успешное замещение переносит соответствующие потребители
на XUnity и удаляет прежние hooks, а не оставляет оба пути активными. Ответственный
за незавершённую игровую проверку не назначен. До неё не заявляется завершение миграции
универсального UI-слоя; общие примитивы и тестовый контур уже переработаны отдельно.

## Почему не записаны маленькие Russian.yml поверх модов

В предоставленном Warfare `LocalizationManager/Localizer.cs` внешний файл выбранного
языка заменяет встроенный и затем дополняется английским. Трёхстрочный русский файл
мог бы вытеснить остальной штатный русский. Поэтому сохранено fill-only добавление
ключей, без переписывания конфигов/полного ресурса мода. Путь источника:
`source-evidence/localization/a/Therzie-Warfare/LocalizationManager/Localizer.cs`.
